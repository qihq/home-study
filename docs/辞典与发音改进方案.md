## 一、现状梳理（源码结构）

### 辞典链路
```
前端查询 POST /dictionary/lookup
  ├─ 单词（纯英文 / 纯中文≤12字）→ 本地 SQLite 词典
  │    ├─ en→zh: ECDICT（word/phonetic/translation/definition，含 exchange 别名）
  │    └─ zh→en: CC-CEDICT（simplified/pinyin/definitions）
  └─ 未命中或短语/句子 → 需配置「电子辞典 AI」(OpenAI 兼容 chat) → LLM 生成 JSON
       （带一次 JSON 修复重试；结果按 query_hash 缓存进 dictionary_entries）
```
- 相关文件：`backend/app/api/dictionary.py`、`backend/app/services/dictionary.py`、
  `backend/app/services/local_dictionary.py`、`backend/scripts/build_local_dictionary.py`

### 发音链路
```
① 词表单词发音（批量任务） backend/app/workers/tts.py
   configured 源 → MimoTtsClient / OpenAiTtsClient → 落盘 .wav → TtsAsset 缓存
   custom 源    → MimoVoiceCloneClient（克隆音色）
② 辞典页播放 POST /dictionary/entries/{id}/audio
   → generate_configured_tts（默认 TTS）或 generate_text_with_voice（克隆音色）
③ 声音克隆（Speaker Profiles / 语音包）
   前端录音 8–30s → 上传 → ffmpeg 转 24kHz 单声道 wav（后端校验 3–30s、base64≤10MB）
   → MiMo voiceclone 合成预览句 → ready 后可设为默认发音
```
- 相关文件：`backend/app/services/mimo_tts.py`、`mimo_speech.py`、`mimo_voice_clone.py`、
  `openai_tts.py`、`tts.py`、`voice_samples.py`、`backend/app/workers/voice.py`、
  `backend/app/api/tts.py`、`settings.py`、`frontend/src/features/dictionary/*`、
  `frontend/src/features/voices/VoiceRecorder.tsx`

## 二、发音：MiMo TTS 官方文档调研 + 问题根因

### 2.1 MiMo TTS 官方接口（已逐页核对官方文档）

项目用的「Mimo TTS」= **小米 MiMo API 开放平台**的 MiMo-V2.5-TTS 系列。

| 项目 | 内容 |
|---|---|
| 平台 | https://platform.xiaomimimo.com/ （Console 申请 API Key：pay-as-you-go 为 `sk-` 前缀；Token Plan 套餐为 `tp-` 前缀，两者不通用） |
| 接口 | `POST https://api.xiaomimimo.com/v1/chat/completions`（OpenAI 兼容，可用 openai SDK） |
| 鉴权 | `api-key: $MIMO_API_KEY` 或 `Authorization: Bearer $MIMO_API_KEY` |
| 模型 | `mimo-v2.5-tts`（内置音色）/ `mimo-v2.5-tts-voicedesign`（文字描述生成音色）/ `mimo-v2.5-tts-voiceclone`（音频克隆） |
| 内置音色 | 中文：`冰糖`(女) `茉莉`(女) `苏打`(男) `白桦`(男)；英文：`Mia`(女) `Chloe`(女) `Milo`(男) `Dean`(男)；默认 `mimo_default` |
| audio 参数 | `format`: wav(默认)/mp3/pcm/pcm16；`voice`: tts 模型可选（默认 mimo_default）；voiceclone 必填且只接受 `data:audio/wav;base64,...`（或 mp3）且 base64 ≤ 10MB；voicedesign 不支持 voice 字段 |
| 硬性规则 | ① 要合成的目标文本必须放 `role: assistant` 的 content；② `user` 消息是可选的风格指令，**内容不会被朗读**；③ 风格控制两种方式：自然语言（user 消息）或 `(style)` 标签 / `[audio tag]`（assistant 文本内），支持语速、情绪、方言、导演模式、`(唱歌)` 等 |
| 流式 | `stream: true` 时 `format` 必须用 `pcm16`，24kHz PCM16LE mono，按 `delta.audio.data` 拼接。voiceclone/voicedesign 的流式目前是「算完一次性返回」的兼容模式 |
| 计费 | 官网标注「Billing: Free for a limited time」 |
| 重要公告 | **MiMo-V2 系列模型已于 2026-06-30 00:00 下线，旧模型名已失效**（官网横幅 + `/docs/updates/deprecate`）。只应用 v2.5 系列模型名 |

官方文档地址：
- API 参考：https://mimo.mi.com/docs/zh-CN/api/audio/tts
- 使用指南（音色表/风格标签/克隆规范/示例代码）：https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5
- 模型下线公告：https://mimo.mi.com/docs/updates/deprecate
- API Key/计费 FAQ：https://mimo.mi.com/docs/zh-CN/quick-start/faq/api-integration

### 2.2 现有实现与官方文档逐项对照

**做得对的**（无需改动）：
- base_url 默认 `https://api.xiaomimimo.com/v1`、`POST /chat/completions`、`api-key` 头 ✅
- 默认模型 `mimo-v2.5-tts`、默认音色 `Chloe`（官方英文女声）✅
- voiceclone 的 voice 字段带 `data:audio/wav;base64,` 前缀 ✅（官方明确要求）
- 目标文本放 assistant、指令放 user ✅（官方硬性规则）
- 克隆样本转 24kHz 单声道 wav、≤30s、base64≤10MB ✅（与官方格式要求一致）

**问题与根因**（按「导致发音错误」的可能性排序）：

1. **【根因 · 原生发音】单词发音错误走错了引擎类型。**
   `mimo-v2.5-tts` 官方定位是「播报/表演式语音合成」——文档通篇是情绪、角色、导演模式、唱歌；它是 LLM 式语音模型，**对单个单词的忠实朗读没有保证**。项目给它的指令是
   `"Speak only the assistant content once."`（`mimo_speech.py`），模型可能忽略该指令而出现：重复读两遍、加语气词、重音/读音错误。这正是「原生的发音经常有问题」的最可能根因。
   **官方接口没有音素/词典式发音参数**——它不适合做词典单字发音源。

2. **【根因 · 模仿声音】克隆发音错误的三个放大器：**
   - 参考音频后端下限仅 **3 秒**（`voice_samples.py`），过短导致音色/韵律提取不稳；前端要求 8–30s 但上传文件走的是后端 3s 校验，3–8s 的样本也能过；
   - **跨语言克隆**：家长大概率用中文样本，拿去读英文单词，官方未承诺跨语言克隆质量；
   - `style_instruction`（中文风格描述）与固定英文指令 `"Speak only..."` 叠加，指令互相干扰。

3. **【bug】`speed`（语速）对 mimo 协议完全无效，却是缓存键的一部分。**
   `MimoTtsClient` 根本不接收/发送 speed（官方接口也确实没有 speed 字段，语速只能用风格指令或标签控制）；
   但 `tts_cache_key()` 包含 speed → 设置里改语速会重新生成全部音频，而内容一模一样。设置界面的语速滑杆是「假功能」。

4. **【bug】音频格式/扩展名三处不一致。**
   `services/tts.py::ensure_tts_asset` 把 WAV 字节写进 `*.mp3` 文件；`api/tts.py` 却以 `audio/wav` 响应；`workers/tts.py` 用 `.wav`。部分播放器/浏览器可能因容器探测失败出现无法播放。

5. **音色与语言不匹配**：默认 `Chloe` 是英文音色；用中文音色读英文（或反之）都会明显劣化。项目没有「按文本语言选择音色」的机制，只有一个全局 voice 配置。

6. **【次要】** 中译英词条的发音取 `primary_translation`（英文释义首条）来朗读——释义若含斜杠/多个词，读出来很奇怪；中文词本身（拼音）没有发音入口。
7. **【次要】** 无重试、超时固定 30s（克隆 45s）、无流式（整句合成完才返回，句子听写首播延迟高——官方已支持 `stream + pcm16` 低延迟流式）。
8. **【提示】** 若用户曾配置旧模型名（如 `mimo-v2-tts*`），2026-06-30 之后会直接报错或串到替换模型；设置界面没有任何模型名校验/提示。

### 2.3 发音改进方案（按优先级）

**P0-1 单词发音换成「真词典发音源」，TTS 只负责句子。**
- 英文单词：优先 `https://dict.youdao.com/dictvoice?audio=<word>&type=1|2`（英音/美音 mp3；今天实测 200、audio/mpeg，国内直连快）；兜底 `https://api.dictionaryapi.dev/api/v2/entries/en/<word>`（免费无 key，返回英/美真人 mp3 URL + 双音标，今天实测可用）。
- 中文词：`dict.youdao.com/dictvoice?audio=<词>&type=2` 实测可用（中文朗读）。
- 落盘本地缓存（复用 `TtsAsset` 或新增 `dictionary_audio` 表，带来源/英音美音字段），一次抓取长期离线可用；抓取失败再降级到 MiMo TTS。
- 效果：单词发音变成真人词典音，100% 忠实，且**不再依赖 TTS 配置**（未配置 MiMo key 时词典页也能出声音）。
- 应用范围：辞典页播放、词表单词批量发音任务（`workers/tts.py` 的 configured 分支先查词典音频源）。

**P0-2 修正 MiMo TTS 调用方式（句子/短语仍走 MiMo）。**
- 去掉 `"Speak only the assistant content once."` 这类易被忽略的指令；按场景构造 user 指令：
  - 听写/学习：`"清晰、中性、匀速的教学朗读风格，只朗读目标文本，不添加任何额外内容。"`
  - 单词兜底（仅当词典源失败）：`"标准词典发音，清晰读一遍这个单词。"`
- `speed` 映射为风格指令（如 `语速稍慢` / `(slow)` 标签），并**修正缓存键**（mimo 协议不再把 speed 混进键，或把 speed 编译进指令后再入键）；openai 协议保持原样（其 `/audio/speech` 原生支持 speed）。
- 按文本语言自动选音色：en→Chloe/Mia/Milo/Dean，zh→冰糖/茉莉/苏打/白桦；设置界面改为「英文音色 + 中文音色」两个下拉（带分组与语言标注）。
- 设置保存时校验模型名必须以 `mimo-v2.5` 开头（或在界面提示 V2 已下线，见官方公告）。

**P0-3 格式统一**：`ensure_tts_asset` 的 `.mp3` 扩展名改为 `.wav`（与 `api/tts.py` 的 `audio/wav`、`workers/tts.py` 一致）。

**P0-4 克隆声音质量**：
- 后端校验下限 3s → 8s（与前端一致），并在录音页给「15–30 秒、安静环境、自然语速朗读给定引导稿」的文案与引导稿（可提供中英各一段供选择，提升跨语言克隆效果）；
- 克隆预览句改为中英各一句（如 `你好，这是家庭学习的声音预览。` + `This is a voice preview for family learning.`），让家长先听清跨语言效果再设为默认；
- 去掉 voiceclone 请求里叠加的固定英文指令，user 消息只放 `style_instruction`（空则留空字符串，官方示例即空串）。

**P1 体验增强（可选）**：
- 句子朗读切流式：`stream: true` + `format: pcm16`，按 24kHz 拼 WAV，首播延迟从「整句生成」降到「首块到达」；
- TTS 请求加重试（1 次指数退避）+ 按文本长度分级超时；克隆/合成任务加并发上限；
- `TtsAsset` 增加过期清理任务（LRU/容量上限），避免 NAS 音频无限增长；
- 辞典页「重新生成发音」按钮语义细分：词典音频源失败时提示换源，而不是盲重试 TTS。

## 三、辞典：成熟方案调研（含今天实测）

### 3.1 现有方案评价
- **ECDICT**（github.com/skywind3000/ECDICT，MIT，8.1k stars，持续更新）已是英文→中文开源词库的最佳选择，选型正确。
- **CC-CEDICT**（CC BY-SA 3.0）做中文→英文正确。
- 但当前**只用了 ECDICT 的一小部分字段**：`pos`（词性，含更准确的标注）没入库（靠正则从 translation 猜 vt./n.）；`collins`/`oxford`/`tag`（中考/高考/CET4 等标签）/`bnc`/`frq`（词频）全被丢弃——这些对儿童学习 app 是最有价值的「词汇分级」信息。
- ECDICT 的 `audio` 字段官方标注「待添加」→ **词库本身没有发音**，所以项目才用 TTS 读单词（也是发音错的根源之一，见 2.3-P0-1）。
- 短语/句子完全依赖 LLM（需家长配 AI key），没有中间层。

### 3.2 可套用的成熟数据源/API（均已在今天实测验证）

| 方案 | 内容 | 许可/费用 | 实测结果 |
|---|---|---|---|
| **dictionaryapi.dev**（Free Dictionary API） | 音标（英/美）、真人发音 mp3 URL、英文释义、例句、词源；数据来自 Wiktionary | 免费、无需 key | `GET /api/v2/entries/en/apple` → 200，返回 uk/us 两个音频与双音标 ✅ |
| **有道 dictvoice** | `https://dict.youdao.com/dictvoice?audio=<word>&type=1(英)/2(美)` 返回 mp3；中文词也可朗读 | 免费公开端点（非官方承诺，需本地缓存 + 兜底） | `audio=apple&type=2` → 200 audio/mpeg ✅；`audio=你好` → 200 ✅ |
| **有道 jsonapi** | `https://dict.youdao.com/jsonapi?q=<word>` 返回英汉双语释义、网络释义等 JSON | 免费公开端点 | 200，39KB JSON（含 web_trans 等）✅ |
| **有道智云开放平台** | 官方翻译/词典 API | 免费额度，需申请 app key | 官方合规方案（ai.youdao.com） |
| **ECDICT 全字段** | 在现有词库上增量入库 `pos/collins/oxford/tag/bnc/frq` | MIT | 无需新数据源 |
| **萌典 moedict.tw** | 中文字典开放数据（拼音/注音、释义、闽南语等） | 开放数据（CC 系） | 可选增强 zh 方向 |

### 3.3 辞典改进方案（按优先级）

**P0-1 查询链升级为三层：本地词库 → 免费在线词典 API → LLM。**
```
单词查询：本地 SQLite 命中 → 直接返回（现状）
        未命中 → dictionaryapi.dev / 有道 jsonapi（免费、确定性）
               → 命中即写入 dictionary_entries 缓存（带来源标注+TTL 30 天，复用现有指纹机制加 api 版本号）
               → 仍失败才走 LLM（仅短语/句子必须 LLM）
```
收益：单词查询质量从「LLM 幻觉风险」变为「权威词典数据」；家长无需配 AI key 也能查词、听发音；LLM 调用量与成本大降。

**P0-2 本地词库构建增强（`build_local_dictionary.py`）**：
- 入库 `pos` 字段（显示词性更准确，替换现有正则猜测逻辑）；
- 入库 `collins`（柯林斯星级）、`oxford`（牛津 3000）、`tag`（zk/gk/cet4/cet6/ielts 等）、`bnc`/`frq`（词频）——前端词条卡展示「中考/高考/CET4」标签与星级，生词本可按词频排序（对儿童学习价值最大）；
- 构建脚本增加 `--download`：自动从 GitHub 拉取最新 ECDICT csv + CC-CEDICT gz，校验 sha256（现有 checksum 机制）后重建；`local_dictionary.fingerprint` 已能让旧缓存自动失效，无需额外改动。

**P0-3 词典结果模型增强（`schemas/dictionary.py` + 前端卡片）**：
- 新增 `phonetic_uk` / `phonetic_us` / `audio_uk` / `audio_us`（或 audio_sources 数组）字段，数据来自 dictionaryapi.dev 或 dictvoice 缓存；
- 单词卡展示英/美双音标，可切换英/美发音；
- 例句：本地命中时用 dictionaryapi.dev 的英文例句补 1–2 条（`examples` 字段已有，目前本地查询恒为空）；
- `exchange` 词形变化（复数/时态/比较级）已有别名表，可在卡片上展示。

**P1 中文方向增强（可选）**：CC-CEDICT 之外接入萌典数据（moedict.tw）或直接用有道 jsonapi 缓存中文→英文词条，让「中译英」也有双语例句；中文词发音用 dictvoice（实测可用）。

**P1 生词本联动**：生词列表接口加 `tag/frq/bnc` 排序选项，家长可优先复习高频/考纲词。
